## Architecture Decisions
- **Data plane**: Gazebo publishes `/robotest/raw/{scan,odom,imu}`; the C++ proxy always publishes `/robotest/{scan,odom,imu}`; validation-only ground truth and contacts stay under `/robotest/validation/*`; `/clock` is Gazebo-to-ROS only.
- **TF ownership**: AMCL owns `map->odom`; the fault proxy owns `odom->base_footprint` in pass-through and drift modes; robot state publisher owns `base_footprint->base_link->sensor frames`; no duplicate odometry TF publisher.
- **Fault timebase**: preload YAML schedules and evaluate against simulation timestamps; record configured/actual times, seed, config hash, affected messages, and parameters. LiDAR dropout omits messages; odometry drift applies one deterministic SE(2) transform to odometry and TF.
- **Metrics**: ground truth defines actual path and collision events; store initial/latest/replan path lengths separately; define efficiency and zero-length handling; align localization error by simulation timestamp; obtain RTF from Gazebo stats and CPU/RSS from process-tree sampling.
- **Supervision**: Go owns ROS child process groups and bounded restart/circuit-breaker behavior; systemd owns only the Go supervisor. `/healthz` means process alive, `/readyz` requires healthy children/heartbeat, all HTTP binds to `127.0.0.1`.
- **Package boundary**: the `.deb` contains the supervisor, wrapper, default/conffile configuration, unit, state/log directory definitions, and docs—not the ROS workspace. Deployable runtime paths use `/opt/robotest-lab` and `/var/lib/robotest-supervisor` so hardening does not depend on a home directory.

1. **Phase 0** — create the repository/evidence skeleton, `config/apt-packages.txt`, `scripts/verify_phase0_preinstall.sh`, `scripts/verify_phase0.sh`, and initial `scripts/verify_all.sh`; record the audit, disk budget, topic/TF/metrics contracts, success/failure criteria, and verification matrix. 5. **Phase 4** — implement `supervisor/`, `scripts/stage_runtime_overlay.sh`, `scripts/verify_phase4.sh`, and Debian/systemd integration with fake-clock/process fixtures, loopback health endpoints, process-group shutdown, stale-heartbeat recovery, bounded backoff and exhaustion. Run `scripts/verify_phase5.sh --local`, create and push the candidate Phase 5 commit, wait for CI on that SHA, run remote verification to record the workflow URL/SHA, create and push an evidence-only commit, then wait for CI and close the phase only after remote verification passes on the evidence commit.

## Edge Cases and Risks
- Software-rendered `gpu_lidar` may be too costly under WSL; begin at 360 rays/5 Hz and simplify before changing hardware assumptions.
- Gazebo is tolerance-repeatable, not bitwise deterministic; use fixed seeds/steps, clean startup, repeated trials, and steady wall-clock escape timers.
- Current host memory is pressured by unrelated containers; never stop them silently, use conservative parallelism, and record any resource-induced limitation.
- GUI capture, GitHub publication, remote CI, or sudo/package operations can fail for external reasons; retain local evidence and leave the affected Definition-of-Done item explicitly incomplete.
